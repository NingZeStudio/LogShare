# 启动器本体实战案例（FCL Issue 提炼）

## Java / JVM

- **Java 版本选择**：≤1.16.5→JRE8；1.17~1.20.4→Java17；1.20.5+→Java21；个别 Mod（如 c2me）要 JDK22——"是 c2me 要 22，不是 fabric 要 22"（#671 #435）
- **1.12.2 Forge 用错 Java**：日志显示实际用了 JRE8 而用户以为配了 11；Forge 1.12.2 在 Java8 下启动不了，需 Java11（#254）
- **GC 实现切换不可用** → Android 的 libc 不提供 shm，需 android-shmem 补丁，部分 JRE 构建不支持（#1120）
- **authlib-injector 对 Java8 小版本敏感**：过低版本连皮肤站会崩端（#37）
- **统一通行证(nide8auth) 接入法**：`-javaagent:./nide8auth.jar=<id> -Dnide8auth.client=true`，开启版本隔离时 jar 放对应 versions 目录（#1364）

## 内存与进程

- **游戏无声无息消失** = 被安卓系统强杀（资源占用过高），不是崩溃、无日志可查；FCL 只能开一个 JVM 进程，无法像 PCL/HMCL 那样附加第二个 JVM 导运行栈（#1556）★ 与 KB 内存卡结论一致
- **32 位设备 (armeabi-v7a)** 只有 1024MB 可分配，只能跑 1.6-1.12 原版（#98）
- 内存分配输入异常数值（如 1500）无效 → 已修（#1018）；内存显示功能已有 CI 构建（#1516）

## ROM / 设备特有

- **卓易通（Windows 子系统类环境）**：jre11+ 必崩，1.16 以下 + 低版本 JRE 可跑（#1164）
- **小米澎湃 OS 2.0 升级后卡加载**：换渲染器无效，等适配（#744）
- **模拟器**：mumu/雷电不行，BlueStacks 可以（#967）；x86_64 下注入回调空指针见 LTW 案例（#1726）
- **华为 Mate60 等新芯片**：初期货架期无可用驱动/渲染器组合（#340）
- 功耗异常偏高（10W+）：手机跑 Java 版常态（#293）

## 控制布局 / 输入

- **启动器反复崩溃打不开？** → 控制布局 JSON 损坏（崩溃时未保存完）。自救：把 `FCL/control` 改名成 `FCL/control_` 再启动（#389）★ 实用冷知识
- 保持触发的虚拟按键松不开（如潜行）→ 已修 CI（#275）；自动保持按键取消失效 → 已修（#271）；编辑按键时崩 → 已修 CI（#298）
- 外接键盘按 E 关物品栏：非 bug——不呼出输入法时无法区分文字与键值（#738）；聊天唤起输入法只能手动，Shift+Enter（#1175）
- 鼠标指针偏移/抖动：高分辨率+特定机型问题，多设备长期存在（#429 #446 #464）
- 分辨率非自动时主界面过大 → MC 自身 UI 缩放逻辑，手动调（#477）

## 文件与下载

- **Forge 安装后启动失败** → libraries 缺文件（如 `launchwrapper-1.12.jar` 没下下来），重装或换源（#846 #156）
- 整合包 JSON 本身损坏 → 找发布者要修正文件（#950）
- 下载慢 → 网络带宽问题，非启动器（#357）

## 其他高价值结论

- **服务器也能在手机上开**：长按启动键走 JAR 执行器（#594）
- **愚人节版误判**：13w 快照被认为不适配 Holy → 特判问题（#1327）
- **b1.2_01~b1.4_01 进服务器名字变 `net.minecraft.launchwrapper.Launch`** → 重启自愈的玄学 bug（#294）
- dynamic_fps 类 Mod 在安卓上创建世界崩 → 该 Mod 假设桌面环境（#197）
- FCL 日志路径：`/storage/emulated/0/FCL/log/`（含 `latest_game.log`），crash-report 在 `.minecraft/versions/<版本>/crash-reports/`（#576 #383 维护者索要日志的标准位置）
