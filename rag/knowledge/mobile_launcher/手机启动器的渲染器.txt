# 启动器·渲染器体系（标准认知模型）

文档更新日期：2026-08-22

## 一、启动器·渲染器体系概述

手机端启动器（如 PojavLauncher、FCL、Zalith 等）本质上是前端界面与后端执行环境（PojavLauncher / Boat）的组合，其核心矛盾在于 Android 设备的 GPU 原生仅支持 OpenGL ES，而 Minecraft Java 版需要 Desktop OpenGL，因此所有渲染器的本质都是图形 API 翻译层或兼容层。架构定位：手机端启动器（Launcher）本质：启动器（前端）+ PojavLauncher / Boat（后端执行环境）、渲染器 = OpenGL→OpenGL ES / Vulkan 兼容层。核心问题：Android GPU 只支持 OpenGL ES，而 Minecraft Java 需要 Desktop OpenGL→所有渲染器本质都是“图形 API 翻译层”。渲染器来源分层：（1）内置 / 默认：Krypton Wrapper（KW）、Holy GL4ES（Holy，旧默认，逐步淘汰）、Large Thin Wrapper（LTW old）、VirGLRenderer（VirGL）、Vulkan Zink（Zink）；（2）插件渲染器（主流扩展）：MobileGlues（MG）、ANGLE、Large Thin Wrapper（LTW new）；（3）兼容 / 过渡 / 已边缘化：LTW（Pojav专用）、VirGL、ANGLE、Holy GL4ES。新增渲染器（2025–2026）：Freedreno——PojavLauncher 新增的桌面 OpenGL 渲染器，面向 Adreno 5xx+ GPU。

## 二、核心渲染器详述

### 1. Krypton Wrapper（KW / NG-GL4ES）

新一代 GL4ES 变体（不是全新架构）、属于 OpenGL → OpenGL ES 翻译路线。介绍：KW采用OpenGL 2.1图形API和相关扩展增强（比 Holy 更完整）、支持 MC 1.17+、兼容范围广，且已内置在启动器中。优点：当前启动器默认 → 优先适配、高版本 MC 兼容显著优于 Holy、性能稳定（通常 ≈ 或优于 Holy）、维护活跃（生态主线）。缺点：本质仍是 GL4ES → 上限有限、部分现代模组/光影仍缺扩展、个别模组存在兼容问题（如特殊渲染管线）。使用场景：默认选择（90%用户）、原版/Forge/Fabric 常规模组、不追求重度光影。状态更新（2026）：Krypton Wrapper 已更新至 0.4.5 版本；已支持 Minecraft 1.21.6+，同时保持对旧版本的兼容；FCL/Zalith 等主流启动器均将其作为默认推荐渲染器；第三方模组包（如 ZALITH OPTIMIZED）明确建议：不熟悉 MobileGlues 配置的用户优先使用 Krypton Wrapper。兼容性详情：支持的 Minecraft 版本覆盖 1.16.5 及以下（0.4.0 显著增强支持），同时也支持 1.17+ 及 1.21.6+。模组兼容性良好，0.4.0 修复了暮色森林和无尽贪婪在 1.16.5 以下版本的问题，0.4.3 修复纹理和帧缓冲子系统并新增 3D 纹理支持。光影方面，0.4.1 修复了 Complementary Shaders 在 Iris 中无法启用的问题，0.4.0 修复了 BSL、Potato、Chocapic13 V6 Lite 等，0.3.0 增强了对实时阴影的支持。整体改善了对 1.16.5- 及 1.17+ 光影包的兼容。已知限制是仍受 GL4ES 限制，特殊渲染管线模组可能有问题，0.4.5 后仓库已归档。GPU 方面对主流 Adreno 和 Mali 支持较好，某些模组包明确推荐在 1.16.5 及以下使用 KW。

### 2. Holy GL4ES

GL4ES 实现（旧版本）。介绍：主要采用OpenGL 2.1。优点：在原版下拥有极高稳定性、老设备（ES2.0）兼容性最好。缺点：无法良好支持MC 1.17和新版 Forge / Fabric。官方已明确：未来会移除 / 不建议使用。使用场景：老设备、运行在MC 1.12.x版本及以下。状态更新（2026）：Holy GL4ES 已有两年未更新；在 Minecraft 25w16a–25w19a 快照版本中已确认完全崩溃，无法正常游玩；与 Sodium 等现代优化模组存在兼容性冲突；官方 Issue 确认问题根源在于“未适配新版 OpenGL 规范”；结论：该渲染器已事实上进入废弃状态，仅建议 MC 1.12.x 及以下老版本使用。兼容性详情：支持所有原版 Minecraft 版本，但在高版本（1.17+）上表现不佳，在 25w16a–25w19a 快照中已确认完全崩溃。与原版兼容性极高，但与 Sodium 等现代优化模组冲突。不支持现代光影方案。对老旧设备（ES 2.0）兼容性最好。已知限制是仅支持 OpenGL 2.1，已进入废弃状态，Holy 在 1.19.4 上可运行但整体不建议。

### 3. MobileGlues（MG）

基于 OpenGL ES 3.x 的原生实现（不是 GL4ES）、接近“真正现代 OpenGL 子集”，没有内置在启动器中。介绍：MG采用OpenGL 3.x图形API、支持现代渲染管线、在Android端是当前唯一“接近原生现代 OpenGL 行为”的方案。优点：Sodium/Iris/Create 支持优秀、光影支持强（Iris / OptiFine /Oculus）、模组兼容性强、性能-画质平衡最好（中高端设备）。缺点：需要 ES 3.0+（老设备不可用）、安装复杂、部分光影仍有限制。使用场景：Fabric+Sodium+Iris、光影玩家、中高端手机。状态更新（2026）：已发布 MobileGlues V2.0.0 正式版；V2.0.0 主要改进：性能优化（特定场景提升显著）、内存占用优化（尤其是长时间运行）、修复 Xaero's World Map 等模组的渲染问题；插件 UI 完全重构，支持 Material/Miuix 双主题切换、横竖屏适配；新增从启动器（FCL/Zalith）借用 ANGLE 库的支持；在高通骁龙8系列芯片上表现尤为出色；已成为 Zalith Launcher 光影/高性能场景的首选渲染器。兼容性详情：运行于 OpenGL ES 3.x 之上（最佳 3.2，最低 3.0），已支持 Minecraft 26.2 以上版本。明确支持 Sodium、JourneyMap、Create、Xaero's World Map 等含自定义渲染管线的模组。光影支持 Iris 和 OptiFine，可加载多种高清光影包，官方维护完整的光影兼容列表（CompatibleShaders.md）和模组兼容列表（CompatibleMods.md）。GPU 方面在高通骁龙 8 系列上表现尤为出色，需要 ES 3.0+，老设备无法使用。V2.0.0 新增从启动器借用 ANGLE 库的能力，但在 Adreno 730/740 上会禁用 ANGLE，或当 Vulkan 1.2+ 不可用时也会禁用。

### 4. Zink（Mesa / Vulkan 路线）【高阶方案】

将OpenGL图形API语言转为Vulkan图形API（Mesa Zink）。介绍：理论可达 OpenGL 4.x（Zink 是目前唯一能在 Android 上提供“接近完整 Desktop OpenGL 4.x 能力”的方案）。优点：解决“缺 OpenGL 扩展”问题、可运行高级光影和依赖 OpenGL 4.x 的模组、对主流 GPU（尤其 Adreno）表现好。缺点：强依赖 Vulkan 驱动质量、容易崩溃、配置复杂（Mesa / Turnip）、兼容性不稳定（主流 Adreno GPU 支持较好，Mali 设备问题较多）。使用场景：高端主流设备、KW / MG 跑不了的模组 / 光影。状态更新（2026）：Mesa 已更新至 26.2 版本，上下文管理从 OSMesa 切换为真正的 EGL 实现（带 Kopper 支持）；骁龙处理器设备限制：目前仅支持旧 Mesa 版本的 Zink 渲染器，使用新 Mesa 版本会导致启动器闪退；Turnip 开源驱动持续更新，已支持骁龙 8 Elite / 8 Gen 5 / 8s Gen 4 等最新芯片，可配合 Zink 开启光影；PojavLauncher 已为 Mali GPU 提供 legacy Zink (23.0.4) 支持（可选插件）；结论：Zink 仍是高阶方案，但受设备/驱动碎片化影响较大，使用前需确认设备兼容性。兼容性详情：理论上支持 MC 1.7+，实际支持的 OpenGL 级别取决于宿主 Vulkan 驱动。可运行依赖 OpenGL 4.x 的模组，但对于 Distant Horizons 等需要 OpenGL 3.2+ 的模组可能存在兼容问题，Iris 即使不使用光影也可能导致问题。支持光影（需配合 VirGL/Zink/MG 渲染器）。GPU 方面对主流 Adreno 较好，Mali 问题较多，PojavLauncher 支持 Mali-Gx7+、Adreno 6xx/7xx，非 Adreno 不建议使用 ZinkKopper。骁龙处理器仅支持旧 Mesa 版本的 Zink，新版本会导致闪退，建议搭配 Turnip 26.0.0_A8xx_test 作为 Vulkan 驱动。已知限制是强依赖驱动质量，容易崩溃，配置复杂，兼容性不稳定，实际支持级别取决于驱动。

### 5. Large Thin Wrapper（LTW）

采用OpenGL 3.0图形API。优点：模组支持良好、可开部分中低配光影。缺点：仅支持 MC 1.17+、已被 KW / MG 挤压。使用场景：Pojav 体系用户。状态更新（2026）：LTW 因许可证问题曾被移出 FCL，现许可证变更后已重新具备集成条件；FCL 现提供两种集成方式：内置集成和插件形式（可独立更新）；社区已出现 LTW-Turbo 增强版项目，目标为 Minecraft 1.17 及以下版本提供持续维护和性能优化；LTW-Turbo 目前处于早期积极开发阶段，尚未发布稳定版；PojavLauncher 最新更新中已修复 LTW 对 Angelica 和 Create: Aeronautics 的兼容性；性能定位：在低端设备上帧率稳定性优于 MG，但 MG 在骁龙8系列上表现更出色。兼容性详情：支持 MC 1.17 及更高版本，LTW-Turbo 重点补齐 1.17 及更早经典版本的渲染支持，但在 1.21.11+ 版本上，LTW 在 Mali GPU 上已知存在问题。模组方面支持 Sodium，PojavLauncher 已修复对 Angelica 和 Create: Aeronautics 的兼容性，但 Xaero 地图模组可能出现颜色显示异常。部分模组包明确确认仅能在 LTW 下工作。光影可开启部分中低配光影，但 Sodium/OptiFine 下启用光影时可能出现黑屏或空白。低端设备帧率稳定性优于 MG，但 1.21.11+ 在 Mali GPU 上有问题。原版 LTW 因许可证问题曾被移出 FCL，现已重新具备集成条件，LTW-Turbo 处于早期开发阶段。

### 6. VirGL

虚拟 GPU（Guest → Host）。介绍：采用OpenGL 4.x图形API、API 类型为Desktop OpenGL（非 ES）、MC理论支持1.7+。优点：可提供 OpenGL 4.x 图形API、绕过设备限制（不依赖手机 GPU 的真实 OpenGL 能力）、兼容极端情况。缺点：CPU / 内存 / 带宽开销巨大（多层调用）、不稳定、已被官方淘汰。使用场景：调试、极端兼容测试。状态更新（2026）：FCL 仍保留 VirGL 作为故障排查手段——卡顿或黑屏时切换至 VirGL 常能解决问题；FCL 的光影支持明确标注“需 VirGL/Zink/MG 渲染器”；状态：仍可用，但非日常推荐，主要作为兼容性兜底方案。兼容性详情：支持 MC 1.7+，支持 OpenGL 4.3。可尝试运行因缺少 OpenGL 扩展而无法运行的模组，但与 Angelica 模组存在不兼容问题（使用压缩顶点格式）。支持光影（需配合 VirGL/Zink/MG 渲染器）。不依赖手机 GPU 能力，理论上绕过设备限制。已知速度极慢，开销巨大，不稳定，FCL 仍保留作为故障排查手段，但已被官方淘汰，将很快被移除。

### 7. ANGLE

Google 开发的图形转换层（OpenGL ES→Vulkan / DX）。介绍：采用OpenGL ES 3.x图形API、能转化后端（Android：OpenGL ES→Vulkan，Windows：OpenGL ES→DirectX，iOS：OpenGL ES→Metal）。优点：驱动兼容性强、稳定性较好（特定设备下）、iOS 平台优势明显。缺点：性能不占优、OpenGL 能力有限、在 Android 上被替代。使用场景：搭载iOS系统的手机。状态更新（2026）：PojavLauncher 的 GL4ES 现已支持与 ANGLE 协同运行；MobileGlues V2.0.0 新增从启动器借用 ANGLE 库的功能；某些文档指出 ANGLE“速度慢于 Holy GL4ES，运行于 Vulkan 之上，仅支持 OpenGL 3.2”；在部分启动器版本中 ANGLE 已被 LTW 替代/移除；结论：ANGLE 在 Android 生态中日渐边缘化，iOS 仍是其主要适用场景。兼容性详情：仅支持 MC 1.17+，仅支持 OpenGL 3.2。可用于加载因缺少扩展而无法运行的模组，但 1.21.x 启用 ANGLE 作为 OpenGL ES 驱动并安装 Sodium 时存在已知 bug。性能不占优，OpenGL 能力有限。在 Adreno 730/740 上禁用 ANGLE，或当 Vulkan 1.2+ 不可用时也会禁用。在部分启动器版本中已被 LTW 替代/移除。Android 生态中日渐边缘化，iOS 仍是其主要适用场景。

### 8. VGPU（Virtual GPU）

虚拟 GPU 渲染，通常基于类似 VirGL / 虚拟化 OpenGL 管线，本质仍是客户端 → 虚拟层 → 宿主 GPU。介绍：支持较高 OpenGL（理论可达 3.x / 4.x，视实现）、完全绕过部分硬件限制。优点：在某些极端情况下：可运行普通渲染器无法运行的模组、可绕过 GPU 驱动缺陷、对“缺扩展”问题容忍度高。缺点：性能极差、延迟高、帧率低、稳定性差。使用场景：仅用于调试 / 验证问题是否为 GPU 驱动导致、极端兼容测试。状态更新（2026）：VGPU 最早于 2023 年出现在 PojavLauncher 分支中（vgpu1.4.0，OpenGL 4.4）；在部分社区整合包（如“异界生活幻想”）中被推荐使用；状态：项目活跃度低，未成为主流方案，仍属于小众/调试用途。兼容性详情：支持较高 OpenGL（理论可达 3.x/4.x），最早于 2023 年出现在 PojavLauncher 分支中（vgpu1.4.0，OpenGL 4.4）。极端情况下可运行普通渲染器无法运行的模组，可绕过 GPU 驱动缺陷。完全绕过部分硬件限制，对“缺扩展”问题容忍度高。但性能极差，延迟高，帧率低，稳定性差。项目活跃度低，未成为主流方案。

### 9. Freedreno（新增）

介绍：Freedreno 是 Mesa 项目的一部分，作为 Adreno GPU 的开源驱动，支持 FCL、ZalithLauncher、Pojav Glow·Worm 等启动器，面向 Adreno 5xx+ GPU 提供桌面 OpenGL 支持。该渲染器尚属新兴方案，暂未列入主推荐梯队。兼容性详情：支持 Adreno 5xx+ GPU，已在骁龙 870 上测试，Adreno 621 和 505 已获支持。但在某些设备上可能存在输入处理问题。目前仍处于早期适配阶段，值得持续关注。

## 三、当前真实推荐优先级（2026年8月更新）

第一优先：MobileGlues——适合模组/光影玩家、中高端设备、追求画质与性能平衡。兼容性最全面，官方维护完整兼容列表。第二优先：Krypton Wrapper——适合绝大多数用户，开箱即用，稳定兼容。对 1.16.5 及以下版本支持不断改善。第三优先：Zink——用于 KW 或 MG 无法运行的极端场景，适用于高端 Adreno 设备。需注意 Vulkan 驱动质量。补充：LTW——适合低端设备、Pojav 体系、1.17+ 常规模组。1.21.11+ 在 Mali GPU 上存在问题。仅兜底：Holy GL4ES——只建议 MC 1.12.x 及以下老版本使用。已在快照中崩溃。忽略：VirGL、ANGLE、VGPU——仅用于调试、兼容性测试或 iOS 特殊场景。VirGL 将很快被移除。额外说明：Freedreno 渲染器虽已出现，但尚属新兴方案，暂未列入主推荐梯队，值得持续关注。
